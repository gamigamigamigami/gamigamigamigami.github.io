Webライター無料公開 + note ¥500

Webライターの始め方｜noteをポートフォリオにして初心者が最初の1件を受注するまで

Webライターを始めたいと思って調べると、勉強法、ブログの作り方、案件の探し方が一度に出てきます。全部を先に終えようとすると、いつ応募すればよいのか分からなくなります。この記事では、募集を見る→noteに見本を作る→応募する→納品する→入金を確認するという順番で進めます。

まず、どこまで行けば「1件目」なのかを決める

Webライターを始めたいと思って調べると、勉強法、ブログの作り方、案件の探し方が一度に出てきます。全部を先に終えようとすると、いつ応募すればよいのか分からなくなります。

この記事では、募集を見る→noteに見本を作る→応募する→納品する→入金を確認するという順番で進めます。勉強法や長期的な単価アップは、1件目が終わってから考えます。

そもそも「Webライターを始める」が、どこまでを指すのかは曖昧です。記事を一本書いたときなのか、応募したときなのか。この記事では、最初の報酬が口座へ入ったところを一区切りにします。

月収や長期的な単価交渉は、今回は扱いません。1件目の納品を通す前には、交渉に使える実績も作業時間の記録も、まだ手元にないためです。

noteは、この記事では販売場所として使いません。発注者に読ませるポートフォリオの置き場にします。収益はnoteではなく、受注した案件から発生する前提です。同じサービスでも目的を混ぜないほうが、公開設定で迷わずに済みます。

準備するのは、パソコン、Googleアカウント、noteアカウント、クラウドソーシングのアカウント、報酬振込用の銀行口座です。有料ツールは1件目の段階では要りません。準備物はこれだけです。次に、いま足りていないものがどれかを見てみます。

手が止まりやすいのは、この3か所

1か所目は学習と応募の境目です。何をどこまで学べば応募していいのかという基準が自分の中に無いので、区切りがつかないまま学習だけが続きます。この区切りは自分では作れません。なぜなら「もう十分だ」と判断できるだけの相場観は、案件の募集要項をまだ見ていない段階では手に入らないからです。

2か所目は実績欄の空白です。クラウドソーシングの提案フォームには「実績」「ポートフォリオURL」を入れる欄があります。まだ見せる記事がなければ、ここで手が止まるのは自然です。先にnoteの記事を作るのは、この欄を埋めるためです。

3か所目は受注後の実務です。レギュレーション（表記ルール）の読み方、Googleドキュメントの共有設定、コピペチェック、WordPressへの入稿、修正依頼への返し方。この領域は学習本にもブログ運営にも出てこないので、初めて受注した時点で初めて遭遇することになります。

本やブログを読んでも、応募の準備は別に残る

本で埋まるのは「文章の型」までです。 PREP法、一文を短くする、主語と述語をねじれさせない。こうした原則は書籍の得意分野で、実際に案件でも毎回使います。一方で、レギュレーションの読み解きやクライアント固有の入稿ルールは発注者ごとに中身が違うため、そもそも書籍化できません。だから何冊読んでも、この部分だけは空白のまま残ります。

ブログ（WordPress）は、ポートフォリオとしては準備に時間がかかります。 ドメイン取得、サーバー契約、テーマ設定、SSL設定を済ませて、ようやく1記事目を書けます。対してnoteは、登録後すぐに記事を書き、公開したURLを共有できます。文章の品質ではなく、見せられるURLを用意するまでの手間が違います。

ただしWordPressの操作経験そのものは、案件では入稿作業として単価に乗る要素になります。つまりブログは不要ではなく、1件目より後に効いてくる投資という位置づけです。両方やる場合の順序は有料部分で扱います。

知恵袋の回答が食い違うのは、質問文に前提が書かれていないからです。 「未経験でも稼げますか」という質問には、ジャンル、週の稼働時間、目標単価、既存スキルのどれも含まれていません。回答者はそれぞれ自分の条件を暗黙に補って答えるので、結論が割れます。参考にするなら結論ではなく、回答者が前提として書いている条件のほうを読んでください。

「勉強を終えてから応募する」という順序が、なぜ終わらないのか

学習を先に置くと、いつ終えるかを自分で決めることになります。ところが知識が増えるほど、まだ知らないことも見えてきます。「もう少し読んでから」が続き、応募の日はなかなか来ません。意欲が足りないのではなく、終わりが見えない進め方だからです。

代わりに、「公開した記事が3本ある」「プロフィールの空欄がない」「提案文のひな形が一つある」と、目で確かめられる目標を置きます。ここまでそろったら応募する、と先に決めておけば、勉強を終えるタイミングで迷いません。

もう一つ理由があります。初心者向け案件の選考では、文章の上手さより先に見られる項目があるからです。募集要項に書かれた条件（文字数、納期、本数、指定ツール、本人確認の完了）に応募が合致しているか、という照合がそれにあたります。ここは学習量と無関係に満たせる部分なので、先に学習を積み増しても応募の通過率にはそのまま反映されません。

あなたの手が止まっている原因が上の3か所のどれかだとすれば、必要なのは追加の学習ではなく、発注者に開かせるURLを3本作ることと、募集要項と1対1で照合できる提案文を1つ持つことです。ここから先は、その3本に何を書くか、どの入力欄に何を入れるか、受注後に何が起きるかを、項目名と手順のレベルで書いていきます。

有料部分の見出しは次のとおりです。

  • 1件目までの順番：何を終えたら次へ進むか
  • ポートフォリオになる3本：何を書くと発注者が判断できるのか
  • クラウドソーシングのプロフィールと提案文：どの欄に何を書くか
  • 単価の計算：提示額と手取りが一致しない理由
  • 受注してから納品までに実際に起きること
