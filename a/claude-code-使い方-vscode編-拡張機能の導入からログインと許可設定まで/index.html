Claude Code 使い方 VSCode編｜拡張機能の導入からログインと許可設定まで

VSCode で Claude Code を使おうとして、最初から戸惑ったかもしれません。「拡張機能を入れれば使える」という説明もあれば、「ターミナルから claude を起動する」という説明も出てくるからです。先に答えを言うと、どちらかが間違っているわけではありません。

VSCode で Claude Code を使おうとして、最初から戸惑ったかもしれません。「拡張機能を入れれば使える」という説明もあれば、「ターミナルから claude を起動する」という説明も出てくるからです。先に答えを言うと、どちらかが間違っているわけではありません。VSCode の中に入口が二つあります。

まず、二つの入口を見分ける

一つは、左サイドバーのチャットパネルから使う方法。もう一つは、VSCode 内蔵ターミナルで claude コマンドを実行する方法です。同じ画面に二つの入口があるので、別の入口を前提にした手順を追うと、途中から話が合わなくなります。手順どおりなのに画面が一致しないときは、まず入口の違いを疑います。

どちらを選ぶかで、後の設定作業の形が変わります。パネル経路ではモードや各種設定、MCP サーバーの追加まで GUI のクリックで行える一方、統合ターミナル経路なら node -v のような通常のコマンドを同じ画面で実行できます。この記事では両方を分けて扱います。

始める前に、アカウントとOSだけ確認する

最初はアカウントです。ログイン画面では、Claude アカウント（Pro / Max / Team / Enterprise）、Anthropic Console アカウント（API 利用）、Amazon Bedrock などの外部クラウド経由から接続方法を選びます。VSCode と拡張機能を入れただけでは、まだ会話は始まりません。

Claude Pro（月額20ドル）を先に契約する手順も見かけますが、Pro だけが入口ではありません。API キーや外部クラウドを使う選択肢もあります。ただし無料プランでは拡張機能からログインできない場合があります。パネルまで表示できたのに先へ進めないなら、拡張機能を入れ直す前にアカウント側を確認します。

2つ目は OS の層です。VSCode 本体のインストールから既に分かれていて、Mac は .dmg を開いて VSCode アイコンを Applications フォルダにドラッグ、Windows は .exe をダブルクリックしてインストーラの指示に従う形。さらに Windows では、VSCode 拡張の Claude Code がシェルとして PowerShell を実行します。だから「使い方 vscode mac」と「使い方 windows vscode」は同じ手順書で追い切れず、コマンドを打つ段になって差が出ます。

「動かない」とき、すぐ入れ直さなくていい

拡張機能はインストール後に自動的に有効化されますが、それでも動作しないことがあります。左側のアイコン一覧にチャットパネルが現れないのも同じ種類の症状で、これは VSCode 側が拡張の状態を読み直していないだけです。再起動すれば反映されます。

パネルが出ているのに反応しない場合は、インストールではなくログインで止まっている可能性があります。認証は拡張機能の中だけでは終わりません。ブラウザで Anthropic アカウントの認証画面を開き、「許可」を押して VSCode に戻るところまでが一続きです。途中でブラウザを閉じると、拡張機能は入っているのにログインだけ終わっていない状態が残ります。

入力欄まで表示されていれば、接続はできています。ここで再インストールを繰り返しても切り分けは進みません。入力欄があるかどうかを境にして、そこから手前なら表示・ログイン・アカウントを、そこから先なら応答内容を調べます。

公式の拡張機能を見分けて入れ、チャットパネルを出すまで

まずはチャットパネルを開けるところまで進めます。

  1. VSCode 左端のアクティビティバーから拡張機能ビューを開き、検索欄に Claude と入力します。
  2. 一覧から公式版を選びます。マーケットプレイスには Anthropic 公式以外の非公式拡張も混ざって表示されるので、提供元が Anthropic であることと、アイコンがオレンジ色の背景に白いウニ状の図形であること、この2点が揃っているものを選んでください。並び順は判断材料になりませんし、片方だけで決めると取り違える余地が残ります。
  3. Install を押します。拡張機能は自動的に有効化されるので、追加の操作は要りません。
  4. 左のアクティビティバーにアイコンが増えたか見ます。増えていれば、チャットパネルを開ける状態です。
  5. 増えていなければ、VSCode 本体と拡張機能を再起動します。インストールの失敗ではなく表示の反映漏れなので、これで出てきます。

VSCode のメニューが英語のままでも、Claude Code とは日本語で会話できます。故障ではないので、いまはそのまま進めて構いません。チャットパネルが開いたら、次はログインです。

有料部分の中身

  • 症状と原因層の対応表（「画面に出ていること／止まっている層／次に触る場所」の3列で7症状ぶん。例：「ログイン画面から先に進まない → アカウントの層 → 拡張の設定ではなくプランか API キー側を変える」）
  • 許可ダイアログに隠れているスコープ切替（this project (just you) の文字列自体がクリックでき、all projects → this project (shared) → this session と循環する4状態の選び分け）
  • プランモードのレビュー往復（プランがチャットではなく中央のエディター領域に出る理由と、範囲選択でコメントを複数付けて返す手順）
  • API キーを設定画面と ANTHROPIC_API_KEY のどちらに置くか、Windows の PowerShell 差、生成コードのハルシネーションを機械的に落とす組み合わせ
  • 3分で終わる接続診断シート（画面で見えた状態を埋めると、次に触る場所が1つに決まる記入式テンプレート）

診断シートは、たとえば次の形で使います。

確認したもの記入例この時点で分かること
左側のClaudeアイコンあるインストールと表示は通過
チャット入力欄ない接続完了前。コード生成の問題ではない
ブラウザ認証許可を押していない次に触る場所はブラウザだけ

設定を片端から変えるのではなく、いま画面に出ているものから次の一手を一つに絞ります。迷ったときに同じ場所へ戻れるよう、記入して使える形にしてあります。
